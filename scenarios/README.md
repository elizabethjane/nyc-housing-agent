# Eval scenarios

A scenario is a planned conversation with an expected outcome taken from the
approved sources, never from the agent's own answers. The process follows
cartwheel's `scenarios/skill/SKILL.md`: agree on dimensions, write grounded
plans, review them with a human, then run.

## Invariants

1. Expected outcomes come from `facts.yaml`, the saved sources, a frozen
   lottery fixture, or the spec. `scenarios/validate.py` recomputes lottery
   answers and checks cited numbers.
2. User messages contain only what a real renter would know or say.
3. Plans are reviewed before any agent run.
4. Coverage and challenge results are reported separately.

## Dimensions (approved 2026-11-10)

| Dimension | Values |
| --- | --- |
| topic | rent_increase, lease_renewal, eviction, security_deposit, fees, lottery_search, lottery_apply, lottery_assets (added 2026-11-10), none |
| style | precise_formal, casual, vague, typo_heavy, rambling_irrelevant, terse, frustrated |
| scope | supported, nyc_housing_unsupported, unrelated |
| intention | neutral, instruction_override, prompt_extraction, link_injection, legal_advice_roleplay, spend_abuse |
| information_given | complete, missing, user_unsure, corrected_later |
| apartment_type | rent_stabilized, rent_controlled, good_cause_covered, good_cause_exempt, unknown, not_applicable |
| location | borough_named, outside_nyc, not_stated |
| lottery_situation (lottery topics only) | several_matches, no_matches, closes_today, closed_named, mitchell_lama, eligibility_unknown, fallback_mode, not_applicable |
| edge_position | none, order_boundary, no_order_for_date, income_at_min, income_at_max, below_min_with_subsidy, rent_at_luxury_limit |

Each scenario also records `turn_count` (1 + number of followups).

## Lottery fixtures

Lotteries change daily, so lottery scenarios are graded against a frozen copy:

```sh
uv run python -m scenarios.capture_lottery_fixture        # writes fixtures/lotteries-<date>.json
uv run python -m scenarios.lottery_answers Brooklyn 2 65000
```

A scenario's `as_of` names the fixture; the runner must freeze the clock at
that date.

## Files

| File | What it is |
| --- | --- |
| `pilot_scenarios.jsonl` | The 12 reviewed pilot scenarios (`pilot-NNN`). |
| `build_full.py` | The full set's plans. Messages are written here; expected outcomes are computed from `facts.yaml`, the saved sources, and the fixtures. |
| `full_scenarios.jsonl` | The full set (`nyc-NNN`), generated by `build_full.py`. Do not edit by hand. |
| `apply_reviews.py` | Accepts a critic model's rewrites only if every number, month and place is unchanged. |
| `message_revisions.json` | The accepted rewrites, with the critic's reasons; `build_full.py` applies them. |
| `fixtures/lotteries-<date>.json` | Frozen open rental lotteries from the Housing Connect API. |
| `fixtures/opendata-<date>.json` | Frozen Open Data backup copy, for backup-mode scenarios. |

## Commands

```sh
uv run python -m scenarios.build_full                                 # regenerate full_scenarios.jsonl
uv run python -m scenarios.validate scenarios/full_scenarios.jsonl    # format and grounding
uv run python -m scenarios.critic scenarios/full_scenarios.jsonl      # leaked facts, repeats, coverage
```

## Runner requirements (for when the agent exists)

- Freeze the clock at the scenario's `as_of` and load the matching fixtures.
- `lottery_query.unknown_ids`: load those lotteries without their income tables.
- `lottery_query.mode: fallback`: make the Housing Connect API unavailable so the agent uses the Open Data copy.
- `rejected_before_model`: the check passes only if no model call is made.

## Running scenarios

Each run calls Claude and costs money. Always pass a budget.

```sh
uv run python -m scenarios.runner scenarios/pilot_scenarios.jsonl --max-usd 3          # the 12 pilot scenarios
uv run python -m scenarios.runner scenarios/full_scenarios.jsonl --max-usd 30 --workers 3
uv run python -m scenarios.runner scenarios/full_scenarios.jsonl --only nyc-004 nyc-095
uv run python -m scenarios.runner scenarios/full_scenarios.jsonl --resume              # finish an interrupted run
uv run python -m scenarios.runner scenarios/full_scenarios.jsonl --regrade             # re-grade saved replies, no API calls
```

Results go to `runs/<name>/results.jsonl` (every turn's reply, tool calls, cost, and check results) and
`runs/<name>/summary.md` (pass, fail, and needs-review counts by group, check, and dimension value).
`scenarios/grade.py` decides each check from the reply text. Checks it cannot decide, and every
human_judgment scenario, are marked needs_review for a person to read.
